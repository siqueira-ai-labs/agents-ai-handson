Fluxo de Atendimento RAG

Referência para montar o fluxo que projeto/nocode_integration.py chama via POST /api/v1/run/{FLOW_ID}, e para exportar como cap_10/langflow_rag_flow.json. Cobre os dois caminhos que o fluxo precisa ter: a indexação da base de FAQ (offline) e a conversa em si (runtime).

01O mecanismo

caminho de dados por requisição indexação (offline) / limite do servidor nó com campo sobrescrevível via tweaks na API

Dois caminhos compartilham o mesmo Chroma DB: a indexação (topo, tracejada) escreve os chunks da base de FAQ uma vez; a conversa (linha central, sólida) lê dele a cada mensagem. O Prompt Template recebe tanto o contexto recuperado quanto a pergunta original do Chat Input — sem essa segunda seta, o modelo veria só os trechos da FAQ, sem saber o que o usuário perguntou.

Nota de nomenclatura: o Langflow não tem uma categoria fixa "Vector Store" na barra lateral — Chroma DB é seu próprio componente (achado buscando "chroma"), e o agrupamento visual varia por versão. Nomes conferidos direto na instância local via GET /api/v1/all (Langflow 1.11.2).

Por que o Parser existe: o Chroma DB devolve cada resultado como um objeto Data com o texto na chave text — não é uma string pronta. O template do Parser tem que ler {text}; um template com {content} (chave que não existe nesse objeto) compila sem erro nenhum, mas produz um texto vazio — o Agent roda normalmente e responde algo como "não foi fornecido contexto", sem nenhum log de erro para achar o problema. Foi exatamente isso que aconteceu na primeira versão deste fluxo; corrigido e testado via POST /api/v1/run.

Por que 3000, não 500: o Embedding Model deste componente só aceita OpenAI, Google Generative AI ou Ollama — Hugging Face não é uma opção aqui, ao contrário do padrão de embeddings locais usado no resto do livro. Com Google (gemini-embedding-2, grátis via Google AI Studio), enviar mais de ~2 chunks no mesmo request de indexação faz a API devolver menos embeddings do que textos enviados — um IndexError dentro do langchain-chroma. Como o FAQ inteiro cabe em ~2KB, um chunk_size de 3000 garante um chunk só, evitando o lote. Não escala para uma base maior sem trocar de provedor.

03Tweaks — o que ex01_multiplas_entradas sobrescreve

Os IDs abaixo (ChatInput-xxxx, PromptTemplate-xxxx) são placeholders — o Langflow gera um sufixo aleatório por nó, e o prefixo pode não bater exatamente com o nome exibido. Pegue os IDs reais na aba API do fluxo depois de montado, e cole em build_tweaks() no gabarito do exercício 1. 

{
  "input_value": "Quero trocar um produto",
  "output_type": "chat",
  "input_type": "chat",
  "tweaks": {
    "ChatInput-xxxx":     { "sender_name": "Ana" },
    "PromptTemplate-xxxx": { "idioma": "português", "tom_resposta": "formal" }
  }
}

04Montagem — passo a passo

  1. Suba o Langflow com LANGFLOW_SUPERUSER/LANGFLOW_SUPERUSER_PASSWORD definidos (ver README atualizado) e abra http://localhost:7860.
  2. Novo flow em branco. Não existe categoria "Vector Store" na barra lateral — use a busca. Arraste Read File → Split Text → Embedding Model → Chroma DB (busque "chroma"; há duas opções, use a chamada exatamente "Chroma DB").
  3. No Embedding Model, só dá pra escolher OpenAI, Google Generative AI ou Ollama (Hugging Face não aparece aqui). Free: Google — pegue uma chave em aistudio.google.com/apikey, adicione como variável global GOOGLE_API_KEY em Settings → Global Variables e escolha o modelo de embedding não-depreciado. No Split Text, use Chunk Size alto o bastante pra base inteira virar 1-2 chunks (ex.: 3000 para um FAQ de ~2KB) — o Google devolve menos embeddings do que textos quando manda 3+ de uma vez no mesmo request, e o Langflow não expõe controle de batch size pra contornar isso. Depois, rode ▶ no Chroma DB para indexar.
  4. Adicione Chat Input, conecte sua saída ao campo search_query do Chroma DB e também direto ao Prompt Template como {question}.
  5. Ligue a saída do Chroma DB a um Parser (não direto ao Prompt Template — o Chroma devolve objetos Data, não texto puro). No template do Parser, use Text: {text} — a chave é text, não content; um template com a chave errada não dá erro nenhum, só produz contexto vazio silenciosamente.
  6. Ligue a saída do Parser ao Prompt Template como {context}. No template, declare também as variáveis {idioma} e {tom_resposta} com um valor default.
  7. Prompt Template → Language Model → Chat Output. Mais simples: use o componente dedicado OpenRouter (busque "openrouter") — já vem com api_key/model_name prontos. Se usar o "Language Model" genérico, selecione provedor OpenAI e preencha base_url/api_key na mão.
  8. Aba API → copie o FLOW_ID e os IDs de ChatInput-xxxx/PromptTemplate-xxxx (confira o prefixo exato, pode variar) para o .env e para build_tweaks() (exercício 1).
  9. Exporte (botão Export) e salve como cap_10/langflow_rag_flow.json.
